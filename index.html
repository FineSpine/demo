Requirements: requirements.txt (Incident Management Service)
Last updated: 2026-11-06 11:05 UTC

a) What is right

  • NotificationService.sendNotification now handles all three severities with -> arms, as the spec requires.
  • RespondentService uses a thread-safe CopyOnWriteArrayList and a clear Optional return, a good fit for the Responder lookup.

b) What is wrong

  • RespondentService.findRespondentByIncident: r.getIncidentId() does not exist on Respondent, which has only respondentId and name. This is a compile error.
  • Respondent is missing the spec's behaviour: category() (primary, secondary, manager, senior manager), noteAcknowledgement(), and getNextRespondent().
  • RespondentService looks up by incident, but the spec routes incidents to respondents by category. Look up the next respondent by category instead.
  • NotificationService: import org.persistence.Main is still unused. Remove it.
  • IncidentManagerService.incidentsById is still never initialized, so registerIncident throws a NullPointerException.
  • IncidentManagerService: severity is still derived from the service name, not the alert.
  • WebController.accept still never calls the manager, the notifier, or the respondent service, so no incident is created on intake.

c) What to do next

  1. Must-have (compile): fix the getIncidentId() call in RespondentService. Either add a field to Respondent or change the lookup to category, which the spec requires.
  2. Must-have (runtime): initialize incidentsById in IncidentManagerService.
  3. Must-have: wire the controller: create the incident, register it, notify, and find the respondent.
  4. Should-have: add the category enum and getNextRespondent() to Respondent: 
    public enum RespondentCategory { PRIMARY, SECONDARY, MANAGER, SENIOR_MANAGER }
  5. Cleanup: remove the Main import in NotificationService.
