Requirements: requirements.txt (Incident Management Service)
Last updated: 2026-11-06 10:57 UTC

a) What is right

  • The if() compile error from the last cycle is fixed.
  • NotificationService is a clean interface that separates the dummy call/email from the core flow.
  • getAndRegisterIncidentFromAlert sets severity and service on the incident, and registers it in one call.

b) What is wrong

  • IncidentManagerService.incidentsById is still never initialized, so registerIncident throws a NullPointerException.
  • IncidentManagerService.getAndRegisterIncidentFromAlert: severity is derived by matching the service name ("payments", "login"). The spec derives it from the alert, not the service name. Use a severity function on the alert fields, e.g. getSeverityFromAlert(Alert).
  • IncidentManagerService: the severity defaults to INFO only through the Incident constructor. Make the default explicit in the severity function.
  • IncidentManagerService.getAndRegisterIncidentFromAlert: the alert fields (serviceId, errorMessage, reportedApi) are not copied to the incident.
  • IncidentManagerService.registerIncident: the duplicate-id branch is still empty.
  • NotificationService is not injected or called anywhere. Severity dispatch (CRITICAL → call, WARN → email, INFO → no-op) is missing.
  • WebController.accept still only logs and acks. It never calls getAndRegisterIncidentFromAlert, so no incident is created on intake.
  • WebController.accept: ResponseEntity<?> and string concatenation in the log call; use ResponseEntity<AlertAcknowledgement> and log.debug("...{}", alert).

c) What to do next

  1. Must-have (runtime): initialize the map: 
    private final TreeMap<String, Incident> incidentsById = new TreeMap<>();
  2. Must-have: call the manager from the controller, then notify. Inject the service and dispatch by severity: 
    Incident incident = incidentManagerService.getAndRegisterIncidentFromAlert(alert);
notificationService.sendNotification(incident);
  3. Must-have: derive severity from the alert with a function, not the service name: 
    private IncidentSeverity getSeverityFromAlert(Alert alert) { ... }
  4. Should-have: copy the alert fields onto the incident, and throw on duplicate ids in registerIncident.
  5. Should-have: implement the dispatch (CRITICAL → call, WARN → email, INFO → no-op) either in NotificationService or a router in the manager.
