LLD Practice Feedback

Requirements: requirements.txt (POST JSON endpoint, HTTP client setup, logging provider)
Last updated: 2026-11-06 10:41 UTC

a) What is right

  • WebController.accept returns a JSON body via SampleResponse, which fixes the earlier plain-string response.
  • ExternalApiService builds a RestClient from the injected builder with a base URL, covering the HTTP setup requirement.
  • SLF4J logging is in place in Main and WebController.

b) What is wrong

  • WebController.accept: the request is still @RequestBody Object. Bind it to a typed request record so input is validated.
  • WebController.accept: return type is ResponseEntity<?>. Use ResponseEntity<SampleResponse> so the JSON contract is explicit.
  • WebController.accept: log.info("..." + args) concatenates eagerly. Use log.info("Received /accept request: {}", args).
  • WebController: import java.util.ResourceBundle is unused. Remove it.
  • Alert is an empty class. It is not used anywhere yet, so either give it a purpose or delete it.
  • SampleResponse: a record is shorter and immutable than the Lombok class.

c) What to do next

  1. Must-have: confirm the endpoint end-to-end. Run the app and call curl -X POST -H "Content-Type: application/json" -d '{"x":1}' localhost:8080/api/accept and check for a JSON body.
  2. Should-have: tighten the signature to a typed record and a typed return: 
    public record AcceptRequest(String name) {}

@PostMapping("/accept")
public ResponseEntity<SampleResponse> accept(@RequestBody AcceptRequest args) {
    log.info("Received /accept request: {}", args);
    return ResponseEntity.ok(new SampleResponse("Accepted!"));
}
  3. Cleanup: remove the unused ResourceBundle import, switch to parameterized logging, and delete Alert if it is not needed.
  4. Optional: convert SampleResponse to a record.
