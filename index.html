LLD Practice Feedback

Requirements: requirements.txt (POST JSON endpoint, HTTP client setup, logging provider)
Last updated: 2026-11-06 09:43 UTC

a) What is right

  • WebController.accept is mapped as POST /api/accept and consumes a request body.
  • ExternalApiService builds a RestClient from the injected builder with a base URL, which covers the HTTP setup requirement.
  • SLF4J loggers are in place in Main and WebController, covering the logging requirement.

b) What is wrong

  • WebController.accept: the body is Object and the response is the plain string "Accepted!". The requirement asks for a JSON response body. Return a small response DTO (e.g. record AcceptResponse(String status)) instead.
  • WebController.accept: @RequestBody Object deserializes to a raw map, not a typed model. Define a request record and accept that type.
  • WebController.accept: log.info(... + args.toString()) can NPE on null bodies and concatenates eagerly. Use log.info("Received /accept request: {}", args).
  • ExternalApiService.getResource returns Object. Prefer a typed return for the consumer, but this is optional for the current requirement.

c) What to do next

  1. Must-have: make /api/accept return JSON. Add a response record and change the return type: 
    public record AcceptResponse(String status) {}

@PostMapping("/accept")
public ResponseEntity<AcceptResponse> accept(@RequestBody Object args) {
    log.info("Received /accept request: {}", args);
    return ResponseEntity.ok(new AcceptResponse("accepted"));
}
  2. Must-have: confirm the JSON response by running the app and calling the endpoint with curl -X POST -H "Content-Type: application/json" -d '{"x":1}' localhost:8080/api/accept.
  3. Should-have: replace Object with a request record so the input is typed.
  4. Optional: type the return value of ExternalApiService.getResource once the downstream response shape is known.
  5. Optional: remove the unused ApplicationRunner bean in Main if it is not needed.
